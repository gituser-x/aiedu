# 工程问题与实现取舍

## 模型返回 JSON，但选项落在不同位置

实际响应可能在顶层或 content 中携带选项，也可能使用字典、字符串列表或富文本字典。统一入口先做结构规范化，再进入业务校验。公开模块直接摘自实际实现，不补造缺失选项和答案。

## 长时间等待后整批失败

多题生成改为批量请求，取消固定 13 秒等待；校验错误携带具体缺失信息重试，已通过的题目保留。返回不足时明确说明缺额。这些机制改善交互，不保证任何提示词都能成功。

## 已登录仍收到无权限提示

实际问题曾是 CSRF Cookie 为 HttpOnly，而前端仅从 document.cookie 读令牌。修复方式是从页面隐藏 CSRF 字段取值，保留 HttpOnly；区分认证失败、安全校验失败与业务权限错误。

## 内容校验需要分层

当前格式、选项、答案引用及缺失配图检查不能证明学科结论正确。内部流程验收中发现过“答案字段与解析最终结论不一致”的数学样本。后续应补充一致性检测、独立复算或审核流程，并分别统计格式成功率、保存成功率和人工内容通过率。

## 可公开性

公开目录按白名单挑选文件，采用全新 Git 历史，避免私有历史遗留凭据。仅公开可审阅的代表性片段；私有模型、完整服务编排、供应商配置和数据均不在仓库中。
